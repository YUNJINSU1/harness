# Brand identity concept boards

Use this branch for a brand identity overview, application, or visual-world board. Standalone logo candidates and lockup development belong to [Logo](logo.md). If the brief includes both new logo development and a board, establish the logo direction first and reuse it across applications; an existing owned logo needs preservation, not another generation phase. The output is an inspectable concept image, not automatic trademark clearance, vector masters, font files, print-ready artwork, or a complete production asset package.

## Choose identity mode

### New identity

Ground the direction in category, audience, product function, emotional promise, positioning, trust needs, name, and cultural context. Derive one core metaphor, then connect logo concept, palette, typography, imagery, and applications to it. A proposed logo must be simple enough to recognize across board panels, but originality and registrability remain unverified until proper design and legal review.

### Provided owned identity

Treat supplied logos, wordmarks, colors, typefaces, icons, imagery, and usage rules as source assets. Preserve logo geometry, wording, proportions, color relationships, and clear space; compose applications around them. Do not replace an owned mark with a generated approximation or reinterpret an established brand merely to make the board more fashionable. Use documented input-image capability where available and inspect the output against the source. If exact preservation is not possible, mark the board proposed/non-approved and identify the affected asset.

Reference brands may guide rhythm, density, material, or presentation quality. Do not copy their mark, name, slogan, distinctive asset, or exact composition.

## Build a coherent brand argument

Name the core metaphor and how it connects the organization to the visual system. Select only the panels needed to make that argument; a concept board need not contain a fixed grid or every possible application.

A useful board may include:

- logo/wordmark focus and concept or construction rationale;
- functional color roles, neutrals, and contrast intent—not decorative swatches alone;
- typography direction showing hierarchy and tone;
- image, illustration, texture, pattern, or icon direction;
- one or more believable digital, physical, environmental, or campaign applications;
- a concise brand promise or verbal-tone sample when supplied or clearly proposed.

Give panels different intensity: a calm identity focus, a functional system view, an emotional image moment, and a believable application can create rhythm without collage clutter. Repeat the same mark, palette logic, type character, image treatment, and metaphor across applications. Applications demonstrate identity behavior; they are not feature demos or proof that packaging, software, signage, or print files exist.

## Keep the system functional

Palette direction should identify roles such as background, foreground, primary action, secondary accent, muted surface, and status color where relevant. Do not claim exact pixel colors were faithfully rendered unless measured from the actual output and approved source. Record known token values separately in the handoff.

Typography direction should communicate role, proportion, weight, case, and pairing. A rendered specimen is not a licensed font file or proof that the named font was used. Distinguish an approved supplied typeface from a proposed category or candidate.

Image direction should reinforce the metaphor, audience, and palette. Use art-directed photography, product imagery, illustration, texture, or abstract systems as appropriate; no mood is mandatory. Avoid unrelated stock scenes and decorative applications that dilute the identity.

## Concept-versus-production boundary

Unless the user separately requests and the environment can actually deliver them, a board provides:

- a visual identity proposal;
- logo and application concepts visible in pixels;
- palette/type/image direction;
- a basis for review and later production.

It does not provide editable vector logo files, final lockups, trademark search, font licenses/files, production color specifications, accessibility validation, dielines, print proofs, or implementation tokens. Never imply those assets can be extracted reliably from generated pixels.

## Inspect and hand off

Open the actual board and check:

1. logo/wordmark consistency across every panel;
2. supplied owned assets against their sources;
3. one coherent metaphor and visual system rather than unrelated mockups;
4. functional palette, readable type hierarchy, and compatible image direction;
5. believable application scale and placement;
6. legible names/taglines, with uncertain pixel text called out;
7. invented claims and production artifacts are not presented as approved.

Regenerate when the mark mutates, brand assets drift, text breaks, or applications cease to belong to one identity. Deliver the board path, new/provided identity mode, concept scope, preserved and proposed elements, known names/tokens/assets, inspection result, and the exact vector/font/production deliverables still absent.
